- #74 [design] Synchroniser le carnet avec le nuage personnel du plongeur : Google Drive, OneDrive (Microsoft), Dropbox et iCloud Drive (Apple), sans serveur OpenDives et sans monétisation. Niveau visé : une vraie synchro dans les deux sens, pas une simple sauvegarde. Le carnet reste un fichier Subsurface (`.ssrf`), lisible par Subsurface sur ordinateur s’il ouvre le même fichier. Technique : (1) Google Drive (API REST v3, accès limité aux fichiers créés ou ouverts par l’app, `drive.file`, ce qui évite l’audit de sécurité de Google), Microsoft Graph pour OneDrive, API Dropbox v2 : connexion OAuth par service, jetons dans le stockage sécurisé de l’appareil, app à inscrire chez chacun ; (2) iCloud Drive : seulement sur iPhone et iPad, sans connexion à gérer (le compte Apple de l’appareil), par le conteneur iCloud de l’app, avec coordination des fichiers et gestion des versions en conflit du système ; aucune API officielle pour Android, donc pas d’iCloud sur Android ; (3) conflits : avant d’écrire, l’app vérifie la version du fichier dans le nuage (révision Drive, eTag OneDrive, `rev` Dropbox, version iCloud) ; si elle a changé, elle télécharge, fusionne avec l’import du cœur (qui reconnaît les plongées en double), puis réécrit : rien n’est écrasé en silence ; (4) hors connexion : file d’attente des envois ; (5) un seul mode à la fois par carnet (cloud Subsurface, dépôt git ou nuage personnel) ; (6) limites : pas d’historique des versions comme avec git, et le fichier entier est envoyé à chaque fois (quelques Mo pour un gros carnet). À dessiner : le choix du stockage (écran Compte, écran Sans compte à côté de « Utiliser mon propre dépôt git », premier lancement), la connexion à chaque service, l’état de la synchro et l’écran de conflit. Effort élevé : à faire après un premier niveau plus simple si on veut (sauvegarde automatique vers un fichier choisi par le sélecteur du système).
